# IPFS 媒体库 使用说明

适用于 `IPFS 媒体库` v0.1.0（Windows x64 绿色包）。

本程序把 IPFS 上的媒体内容按「专辑」组织：一个本地文件夹对应一个专辑，上传后生成专辑 CID 并写入本地数据库；数据库快照会发布到 IPNS，其他人订阅该 IPNS 后即可看到你的专辑列表。

---

## 1. 软件简介

- **专辑制管理**：以文件夹为最小单元，专辑名即文件夹名。
- **本地节点**：程序本身不内置 IPFS 节点，读写都通过本机 kubo（IPFS Desktop 自带）的 HTTP API 完成。
- **在线预览**：视频、音频通过本地网关流式播放；图片、文本通过 API 读取后显示。
- **发布与订阅**：上传/删除后自动把数据库发布到 IPNS；可订阅他人的 IPNS 数据源（只读）。
- **绿色包**：解压即用，无需安装 .NET 运行时；配置与数据库保存在程序目录旁。

---

## 2. 运行环境与前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11，64 位 |
| 运行时 | 无需单独安装（发布包已自包含 .NET 8） |
| IPFS 节点 | IPFS Desktop（推荐）或 kubo 命令行节点，需保持运行 |
| HTTP API | 默认 `http://localhost:5001` |
| 视频网关 | 默认 `http://localhost:8080` |
| 磁盘空间 | 程序约 210 MB，另需预留 IPFS 仓库空间 |

### 2.1 启动节点

- **IPFS Desktop**：启动后等待状态显示为「已连接」即可，默认同时提供 5001 API 与 8080 网关。
- **kubo 命令行**：

```powershell
ipfs daemon
```

需确认配置中 API 监听 `127.0.0.1:5001`、网关监听 `127.0.0.1:8080`：

```powershell
ipfs config Addresses.API
ipfs config Addresses.Gateway
```

### 2.2 验证连通性

打开程序「设置」页：

- 点击 HTTP API 行右侧「测试」，显示「连接成功，节点版本 …」即正常。
- 点击视频网关行右侧「测试」，显示「网关可达（HTTP …）」即正常。

节点未启动时，程序仍可打开，但专辑列表可能为空、预览与上传会报连接失败。

## 3. 安装与启动

### 3.1 解压

1. 解压 `IPFS.Avalonia-win-x64.zip` 到任意**可写**目录，例如 `D:\Apps\IPFS媒体库`。
2. 保持目录结构完整，不要单独移动 `IPFS.Avalonia.exe`：`libvlc\` 与 `*.dll` 必须与 exe 同级。
3. 双击 `IPFS.Avalonia.exe` 启动。

### 3.2 首次启动

首次运行会在 exe 旁自动创建 `Data` 目录与专辑数据库；其余文件按需生成：

```text
<程序目录>\Data\
├─ IPFSData.db        # 专辑数据库（SQLite，首次启动创建）
├─ settings.json      # 配置，首次修改设置/订阅/主题时生成
├─ Subscriptions\     # 订阅缓存，首次订阅时生成
├─ Publish\           # IPNS 发布暂存（临时），发布时生成
└─ app-error.log      # 错误日志，产生日志时生成
```

> 未签名程序首次运行可能弹出 SmartScreen 提示，选择「更多信息 → 仍要运行」即可。

### 3.3 升级

1. 退出程序。
2. 备份 `Data` 目录（至少 `IPFSData.db` 与 `settings.json`）。
3. 用新版本文件覆盖程序目录，**保留** `Data` 目录。
4. 重新启动。

### 3.4 为什么不要安装到 Program Files

数据目录固定在 exe 旁，而 `C:\Program Files` 默认不允许普通用户写入，会导致无法保存配置与数据库。请放在用户可写目录（如 `D:\Apps`、`%LOCALAPPDATA%`）。

## 5. 上传专辑

### 5.1 目录约定

- 专辑名 = 选择的文件夹名。
- 文件夹内的文件与子目录会按相对路径保留。
- 建议把封面放在专辑根目录，命名为 `Cover.jpg` / `Cover.png` 等（不区分大小写，主文件名必须是 `Cover`）。
- 简介文件同理，放在专辑根目录并命名为 `Content.txt` / `Content.md` 等（主文件名必须是 `Content`）。
- 这两个特殊文件在详情页文件列表中固定显示在最前（封面在前、简介其次），其余文件保持原有顺序；放在子目录中的同名文件不会被提前。

示例：

```text
我的专辑\                 → 专辑名「我的专辑」
├─ Cover.jpg              → 专辑封面
├─ 01.mp4
├─ 02.mp4
└─ 字幕\
   └─ 01.srt
```

对应的 IPFS 路径为 `<专辑CID>/01.mp4`、`<专辑CID>/字幕/01.srt`。

### 5.2 上传流程

1. 首页点击「上传专辑」，选择文件夹。
2. 程序遍历文件并逐个上传，状态行显示当前进度。
3. 上传完成后：
   - 得到文件夹 CID（专辑根 CID）；
   - 写入本地数据库；
   - 把数据库快照上传并发布到当前 IPNS 发布密钥。

上传大目录时界面仍可操作，可随时点击取消。

### 5.3 取消与失败

- **取消上传**：请求被中止，专辑不会写入数据库，IPNS 也不会更新。节点中可能残留未固定的数据块，可在设置页用「清理未固定数据」回收。
- **上传失败**：状态行与设置页「运行日志」显示原因，常见为节点未启动或网络异常。
- **发布失败**：专辑已保存到本地数据库，只是 IPNS 未更新；稍后再次上传或删除会触发重新发布。

## 6. 浏览与预览

### 6.1 打开专辑

双击卡片/列表行，或右键「打开」。详情页左侧是文件列表，右侧是预览/播放区。

老版本写入的专辑若没有文件清单，打开时会自动从 IPFS 补取；也可点文件列表上方的刷新按钮重新拉取。

文件列表的顺序：

- 根目录的封面（`Cover.*`）与简介（`Content.*`）固定在最前，其后是其余文件；
- 其余文件保持上传时的目录枚举顺序，不做重排；
- 打开专辑时默认选中第一个普通文件，不会停在封面或简介上；
- 刷新文件列表后会保持刷新前的选中文件。

### 6.2 支持的预览类型

| 类型 | 扩展名 |
|---|---|
| 视频 | `.mp4` `.mkv` `.avi` `.mov` `.flv` `.wmv` `.ts` `.webm` `.m4v` `.mpg` `.mpeg` |
| 音频 | `.mp3` `.wav` `.flac` `.aac` `.m4a` `.ogg` `.opus` `.wma` `.aiff` `.ape` |
| 图片 | `.jpg` `.jpeg` `.png` `.gif` `.bmp` `.webp` |
| 文本 | `.txt` `.md` `.json` `.xml` `.csv` `.log` `.srt` `.ass` |

其他类型会提示「暂不支持预览，可下载后查看」。

说明：

- 视频/音频通过本地网关 `http://localhost:8080/ipfs/<CID>` 流式播放，首次播放取决于本地节点是否已有数据，可能需要等待。
- 图片通过 API `cat` 读取并缩放到 1280×800 内显示；大图首次加载稍慢。
- 文本通过 API 读取，最多显示前 64K 字符，超出会提示已截断。

### 6.3 播放控制

- 双击文件或点击「播放选中文件」开始播放。
- 控制条：播放/暂停、停止、打开本地视频、静音、音量、进度拖动、影院模式。
- 影院模式隐藏专辑信息与文件列表，播放器占满窗口。
- 切换到非音视频文件时，正在播放的音频/视频会自动停止。

### 6.4 文件操作

- 文件右键：下载文件、复制 CID。
- 列表顶部按钮：播放选中、下载选中、从 IPFS 刷新。

## 7. 下载

### 7.1 下载打包文件

- 通过 kubo 的 `get` 下载整个专辑并保存为 `<专辑名>.tar`。
- 归档内顶层目录名是专辑根 CID（UnixFS 节点本身不保存名字）。
- 下载过程不显示逐文件进度；大专辑请耐心等待，中途失败可直接重试（tar 不支持断点续传）。

### 7.2 下载专辑（解包为文件夹）

- 选择目标目录后，程序会在其下创建 `<专辑名>` 文件夹并逐条解包。
- 若目标文件夹已存在，会先弹出覆盖确认；确认后替换整个目录。
- 解包过程使用临时目录与备份目录：
  - 成功：旧目录删除，新目录就位；
  - 失败或断网：旧目录保持不变，临时目录会被清理。
- 下载完成后会按数据库中的文件清单校验文件数量；清单为空的旧专辑跳过数量校验。
- 路径中的非法字符会被替换为 `_`，子目录层级保持不变。

### 7.3 网络中断时

- 连接被拒绝、超时、传输中断都会以错误提示结束，不会写入不完整的新目录。
- 若连接恰好断在 tar 条目边界，tar 可能「正常结束」，此时依靠文件数量校验发现不完整。

## 8. 发布与订阅

### 8.1 基本概念

- **CID**：IPFS 内容地址，内容不变 CID 不变；专辑根 CID 变化代表内容有增删改。
- **IPNS**：指向某个 CID 的稳定地址。你的数据库每次发布后，IPNS 名会指向新的数据库 CID。
- 本程序发布的目录固定包含两个文件：数据库快照 `IPFSData.db` 与 `manifest.json`（含仓库名称、发布时间、校验摘要）。

### 8.2 选择发布密钥

在「设置 → IPNS 密钥」中：

1. 点击「刷新」读取本机所有密钥。
2. 在「发布密钥」下拉框选择用于发布的密钥（默认 `self`）。
3. 下方「当前发布密钥」一行显示：密钥名 · 完整 IPNS 地址。
   - 显示「（节点上不存在该密钥）」表示所选密钥已被删除；
   - 显示「（IPNS 地址未加载）」表示尚未从节点读取成功。
4. 选择后立即保存；切换密钥只影响今后的发布，已订阅旧地址的用户不会自动迁移。

新建密钥可用命令行：

```powershell
ipfs key gen 我的发布密钥
ipfs key list -l
```

### 8.3 分享订阅源

点击「当前发布密钥」行右侧「分享」，会复制一段文本，包含：

- 数据仓库名称
- 完整 IPNS 地址
- 发布密钥名
- 生成时间
- 订阅方法与提示

对方在「设置 → IPNS 订阅」粘贴该地址即可订阅。

### 8.4 订阅他人

1. 在「IPNS 订阅」输入 IPNS 名称或 `/ipns/` 地址（如 `k51…`、`example.com`）。
2. 「别名」可选，用于左栏显示；留空则跟随远端仓库名称。
3. 点击「订阅」，程序下载远端数据库到本地。
4. 订阅成功后会出现在左栏，数据只读（不能上传、删除）。

订阅端只保留当前版本与上一版本，便于回滚。

### 8.5 更新、回滚与取消订阅

所有操作入口都在「设置 → IPNS 订阅」：每条订阅右侧有「更新」「恢复上一版本」「取消订阅」三个按钮，列表下方有「更新全部订阅」。

每条订阅会显示三行信息：**状态**、**当前版本的远端 CID**、**最近检查时间**。状态含义：

| 状态 | 含义 |
|---|---|
| 未下载 | 已写入配置但本地还没有数据库文件 |
| 成功 | 最近一次更新成功获取了新版本 |
| 已是最新 | 远端 CID 与本地一致，只刷新了检查时间 |
| 已恢复（非最新） | 已回滚到上一版本，远端已有更新的版本 |
| 失败 | 最近一次更新失败，本地数据保持不变 |

#### 8.5.1 更新单条订阅

1. 点击该订阅右侧「更新」。
2. 程序解析 IPNS → 读取远端 `manifest.json` → 比对远端 CID 与本地记录的 CID。
3. 结果：
   - **CID 相同**：状态变为「已是最新」，最近检查时间刷新，其他不变。
   - **CID 不同**：下载新数据库，校验 SHA256 与数据库可打开性后，把旧 `current.db` 轮换为 `previous.db`，新文件成为 `current.db`；状态变为「成功」，左栏列表随之刷新。
4. 底部结果行显示 `[订阅名] 已更新到新版本。` 或错误原因。

更新失败时（IPNS 无法解析、远端 manifest 无效、schema 版本不支持、下载中断、校验不通过），状态变为「失败」，**现有 `current.db` 与 `previous.db` 都不会被改动**，临时文件 `current.download` 会被清理。

#### 8.5.2 更新全部订阅

点击「更新全部订阅」，程序按列表顺序逐条执行与 8.5.1 相同的更新流程。

- 单条失败不会中断后续订阅，失败项状态单独标记为「失败」。
- 全部执行完毕后结果行显示「已更新全部订阅。」
- 执行期间「更新」「恢复上一版本」「取消订阅」均不可点，避免同时改写订阅目录。

#### 8.5.3 恢复到上一版本

「恢复上一版本」按钮只有在存在上一版本时才可点（即已经成功更新过至少一次）。

1. 点击该订阅的「恢复上一版本」。
2. 弹出确认框：`将[订阅名]切换到上一版本数据库？当前版本会保留为备份，可再次恢复。`，选择确认。
3. 程序在订阅目录内交换 `current.db` 与 `previous.db` 两个文件，并交换记录中的「当前 CID」与「上一版本 CID」。
4. 状态变为「已恢复（非最新）」，左栏专辑列表立即按回滚后的数据库刷新。

要点：

- 回滚只切换本地数据库副本，不修改 IPFS 上的任何数据，也不影响发布方的 IPNS。
- 只能往回退一版：订阅端永远只保留两个文件，更早的版本不会留存。
- **回滚是可逆的**：再次点击「恢复上一版本」会换回原来的版本。
- **回滚后点「更新」会回到最新**：远端 CID 与本地不一致，程序会重新下载最新版本；此时被替换下来的旧版本成为新的「上一版本」。
- IPNS 本身有记录过期时间（默认 24 小时），若远端长期未发布，回滚成功但后续「更新」可能因无法解析而失败。

#### 8.5.4 取消订阅

1. 点击该订阅的「取消订阅」。
2. 弹出确认框：`确定取消订阅[订阅名]？本地已下载的数据库与备份将被删除。`，选择确认。
3. 程序依次执行：
   - 先从 `current.db` 读出该订阅的专辑根 CID 清单（删目录前完成）；
   - 从订阅列表与 `settings.json` 中移除该订阅；
   - 删除 `Data\Subscriptions\sub-xxxxxxxx\` 整个目录（含 `current.db`、`previous.db`）；
   - 对该库中**已缓存到本地**的远程专辑执行解除固定。
4. 底部结果行显示「已取消订阅[订阅名]。」，左栏对应数据源消失。

解除缓存固定的规则：

- 与本地专辑 CID 相同的跳过（本地专辑仍在使用）；
- 与其他订阅仍在引用的 CID 相同的跳过；
- 未被固定的跳过；
- 单个专辑解除失败只写日志，不阻断取消订阅。

若发生跳过，日志会提示「已解除 N 个专辑的缓存固定（空间将在设置页清理仓库时释放），M 个因被其他数据源引用而保留」。解除固定只是取消 pin，数据块需在「设置 → 仓库维护 → 清理未固定数据」后才真正释放。

#### 8.5.5 订阅目录结构

```text
Data\Subscriptions\
└─ sub-3f2a91bc\        # 目录名 = "sub-" + IPNS 名的 SHA256 前 8 位
   ├─ current.db        # 当前使用的版本
   ├─ previous.db       # 上一版本，用于回滚
   └─ current.download  # 仅下载中存在，成功或失败后都会清理
```

> 手工备份订阅数据时复制整个 `Data\Subscriptions\` 即可；只复制 `current.db` 会失去回滚能力。

### 8.6 定时更新

在「订阅定时更新」中启用，并选择间隔：10 分钟、30 分钟、1 小时、6 小时、24 小时。

- 计时从程序启动后的第一个间隔开始，启动时不会立即检查。
- 关闭程序后不再更新。

### 8.7 缓存远程专辑

远程专辑默认只显示元数据，实际内容可能不在本机。右键可：

- **缓存到本地**：递归固定专辑根 CID 到本地节点，之后可离线预览/播放。
- **删除本地缓存**：解除递归固定，释放仓库空间（数据块需再执行「清理未固定数据」才会真正删除）。
- **取消缓存**：缓存进行中再次点击可中止。

## 10. 数据文件与备份

| 路径 | 内容 | 是否可删 |
|---|---|---|
| `Data\settings.json` | 全部配置（连接、主题、密钥、订阅、定时更新） | 删除后回到默认值 |
| `Data\IPFSData.db` | 专辑数据库（名称、CID、文件清单、日期） | 删除会丢失专辑列表（IPFS 数据仍在节点） |
| `Data\Subscriptions\` | 订阅的远端数据库副本与上一版本 | 删除后需重新订阅 |
| `Data\Publish\` | 发布前生成的数据库快照 | 可删，下次发布会重建 |
| `Data\app-error.log` | 错误日志 | 可删 |
| `libvlc\` | 播放器原生库与插件 | 不可删，否则无法播放 |

说明：

- `settings.json` 固定位于 `exe\Data\settings.json`，即使修改了「数据根目录」也不会改变它的位置。
- 其余数据（数据库、订阅、发布暂存、日志）跟随「数据根目录」。
- IPFS 内容本身保存在 IPFS Desktop/kubo 的仓库中（通常在 `%USERPROFILE%\.ipfs`），不在本程序目录。

**备份建议**：退出程序后，整体复制 `Data` 目录即可；若换电脑，还需在节点侧保留/迁移 IPFS 仓库。

## 11. 常见问题

### 11.1 列表为空、提示连接失败或 500 错误

节点未启动或 API 地址不对。确认 IPFS Desktop 正在运行，或在设置页点击 API「测试」。

### 11.2 视频黑屏 / 无法播放

- 检查「视频网关」地址与「测试」结果。
- 确认网关监听 8080，且 `http://localhost:8080/ipfs/` 可访问。
- 远程专辑未缓存时，首次播放需要从网络拉取数据，可能很慢或超时。

### 11.3 图片能预览但视频不能（或相反）

图片走 API `cat`，视频走网关。两条路径分别依赖 API 与网关，需分别检查。

### 11.4 日志出现 `could not resolve name`

示例：`name/resolve ... offline=true` 返回 500 `could not resolve name`。

原因：本机没有该 IPNS 名的有效解析记录（从未发布，或记录已过期，默认有效期 24 小时）。离线解析只查本地记录，不影响本次启动与已发布内容；重新发布或联网解析后会恢复。

### 11.5 日志出现 `'to' cid was already recursively pinned`

示例：`pin/update ... 'to' cid was already recursively pinned`。

原因：新根 CID 在上传时已被 `add` 默认递归固定，`pin/update` 再固定一次必然报此错误。程序已有兜底处理，不影响发布结果，可忽略。

### 11.6 下载专辑提示目标已存在

程序会询问是否覆盖。覆盖采用「先备份旧目录、再换入新目录」的方式，失败时会回滚，原目录不会被破坏。

### 11.7 删除专辑失败

删除会先解除 IPFS 固定，再删数据库记录。解除固定失败（节点未启动、网络异常）时会中止删除并保留记录，排查节点后重试。

### 11.8 磁盘占用越来越大

- 在设置页执行「清理未固定数据」。
- 历史发布产生的旧数据库版本、已解除固定的远程缓存，可能仍占用仓库空间，需清理后由节点回收。
- 本地专辑是固定状态，不会被清理，请按需删除专辑。

### 11.9 能否放到 Program Files 或做成安装包

当前为绿色包，数据写在 exe 旁，不能放只读目录。若要安装到 Program Files，需要把数据目录改到 `%LOCALAPPDATA%` 后再制作安装包。

### 11.10 局域网的手机/其他电脑能否访问

本程序只负责桌面端展示，不提供移动端页面。可让同一局域网设备访问 PC 上的网关，例如：

- 把 kubo 网关监听改为 `/ip4/0.0.0.0/tcp/8080`；
- 在系统防火墙放行 8080；
- 手机浏览器访问 `http://<PC 局域网 IP>:8080/ipfs/<CID>`。

注意：网关对外开放会让同网段设备读取你的内容，也可能触发节点向网络宣告数据，请自行评估隐私风险。

### 11.11 发布到 IPFS 会被审查吗，能查到发布者吗

- 协议本身不审查内容，但公共网关、公共固定服务会按各自策略屏蔽内容。
- CID 不包含作者信息；IPNS 名是稳定的假名，但长期使用可被关联。
- 节点会向 DHT 宣告自己提供数据；与陌生节点直连时对方能看到你的 IP。使用公共网关时，网关也会记录请求。
- 如需更强匿名性，应在网络层与节点层另行处理，本程序不提供匿名化能力。

## 12. 已知限制

- 以专辑（文件夹）为最小单元，暂不支持在专辑内单独增加或删除文件；调整内容需要重新上传该文件夹。
- 下载打包文件（tar）不支持断点续传。
- IPNS 记录默认 24 小时过期，长期不发布时订阅端可能解析失败。
- 订阅数据只读，不能直接编辑远端仓库。
- 绿色包数据写在 exe 旁，不适合安装到 `Program Files`。
- 程序未签名，首次运行可能触发 SmartScreen 提示。
